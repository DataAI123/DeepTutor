DeepTutor 的核心设计思想是 "Agent-Native"：将 LLM 的原生能力拆解为两层可组合的模块。Level 1 Tools 是 LLM 按需调用的原子函数；Level 2 Capabilities 则拥有完整的 turn 控制权，内部可能经历多轮迭代。所有模块通过统一的 StreamBus 事件通道与三种入口（CLI、WebSocket、Python SDK）解耦。

② 双层插件模型

🔧

Level 1 — Tools

单次函数调用，LLM 按需选择。每个 Tool 实现 BaseTool 接口，提供 JSON Schema 元数据和 execute() 方法。系统支持用户切换启用、自动挂载（基于上下文条件）、以及 deferred 渐进式加载。

→ "我需要搜索 web" → 调用 web_search()

🎭

Level 2 — Capabilities

拥有 turn 控制权的多阶段流水线。内部驱动完整的 agentic loop，可注册自己的 Tools（owned_tools），通过 LoopExtension Protocol 与系统集成。KnowledgeCapability 模式独占工具面。

→ "深度解题" → deep_solve (planning→reasoning→writing)

关键设计差异

维度Level 1 ToolLevel 2 Capability
执行方式单次 async execute()驱动完整 agentic loop
控制权LLM 在 loop 内按需调用接管整个 turn 的生命周期
工具面被 LLM 选择使用可注册 own_tools，或独占 (KnowledgeCapability)
System Prompt出现在工具列表通过 system_block() 贡献 prompt 片段
终止返回 ToolResult 即可Loop 直到 terminal label 或 max_iterations
交互可 pause_for_user 但控制权返回 loop完整的 on_user_pause / on_user_resume 生命周期钩子

③ 核心数据结构

UnifiedContext — 统一上下文

贯穿整个系统的单一数据对象，从 Orchestrator 流入每个 Tool / Capability / Plugin。所有入口都填充同一个 UnifiedContext，保证语义一致性。

@dataclass
class UnifiedContext:
    session_id: str           # 持久会话标识
    user_message: str          # 当前用户输入
    conversation_history: list # OpenAI 格式历史
    enabled_tools: list | None # 用户显式启用的 L1 tools
    active_capability: str | None # 选中的 L2 Capability
    knowledge_bases: list      # RAG 使用的 KB 名
    attachments: list          # 图片 / 文件
    config_overrides: dict     # 本次请求的临时配置
    memory_context: str        # 注入 system prompt 的记忆文本
    persona_context: str       # 人设指令
    skills_manifest: str       # Skills 清单
    runtime: TurnRuntimeContext # 运行时回调（不可序列化）
    interaction: InteractionState # 可变交互状态
    capability_output: CapabilityOutput # Capability 结构化输出
    extension_state: dict      # 各 Extension 独立命名空间

ToolDefinition — 工具元数据

描述 Tool 的 JSON Schema，用于构造 LLM 的 function-calling schema。支持两种模式：parameters 列表（标准化）和 raw_parameters（直接透传 JSON Schema，用于 MCP 等外部适配）。

ToolResult — 工具返回

@dataclass
class ToolResult:
    content: str               # 返回给 LLM 的文本
    sources: list[dict]        # 引用来源（流事件）
    metadata: dict             # 自由结构 payload
    success: bool              # 显式失败标志
    pause_for_user: dict | None # 暂停等待用户回复
    terminate_turn: bool       # 终止 turn（保留兼容）

④ Agentic Loop 机制

DeepTutor 的核心执行引擎是一个 标签驱动的迭代调度器 (run_agentic_loop())。它不依赖单一固定的 prompt 结构，而是让每个 Capability 声明自己的标签词汇 (LabelProtocol)，LLM 每轮以一行标签开头。

LabelProtocol — 标签协议

每个 Capability 声明 5 种标签分类：

FINISH终止标签 — 结束 loop 并产出最终响应文本
THINK中间标签 — 推理过程，文本保留为 assistant context
TOOLS工具标签 — 本轮包含 tool_calls，执行后继续 loop
PAUSE终态+可流式 — 向用户输出旁白但不结束 turn

LoopHost — Capability 回调接口

Loop 核心保持通用，所有特定行为通过 LoopHost Protocol 回调：

# 关键钩子
guard_context_window()        # 裁剪消息窗口
dispatch_tools()                # 并行执行 tool_calls
resolve_pause()                # 处理 pause_for_user
emit_final()                     # 流式最终文本
emit_terminator()               # Tool 终止时的最终事件
force_finalize()                # max_iterations 耗尽时的恢复策略
validate_terminal()             # 有状态的终端标签校验

协议违规修复

Loop 检测三类违规并自动修复重试：

  • missing_label — 首行无有效标签
  • multiple_labels — 文本内嵌入多个标签
  • {label}_with_tools — 非 TOOLS 标签却携带 tool_calls
  • tool_without_calls — TOOLS 标签却无实际调用

修复流程：保留模型草稿 → 注入 correction prompt → 继续下一轮迭代。

⑤ 流事件系统 (StreamBus)

所有 Capability 和 Tool 都通过 StreamBus 发布事件，消费者（CLI 渲染器、WebSocket 推送、JSON 写入器）订阅同一个通道。这是生产者-消费者解耦的关键。

StreamBus 核心机制

emit(StreamEvent)
生产者推送事件到所有订阅者队列
│
subscribe(after_seq=N)
异步迭代器 — 支持从历史回放 + 实时推送
│
多消费者 fan-out
每个订阅者独立 asyncio.Queue，跨 loop 安全

关键实现亮点

  • 跨事件循环安全：为每个订阅者记录其所属 event loop，跨 loop 用 call_soon_threadsafe 投递
  • 历史回放：新订阅者自动回放 _history 中已发出的事件，支持断线重连
  • seq 序列号：可选分配单调递增序号，客户端可通过 after_seq 增量订阅
  • 阶段上下文：stream.stage(name) 作为 context manager 自动发射 STAGE_START / STAGE_END
  • WAIT_FOR_INPUT：完整的暂停-回复机制，通过 stream.wait_for_input(prompt) 暂停并注册 input_listener

Deferred Tools — 渐进式加载

标记为 deferred=True 的 Tool（主要是 MCP 外部工具）不会出现在初始工具列表中。System Prompt 只列出一行入口；LLM 可通过 load_tools 主动拉取完整 schema，实现大规模外部工具的按需暴露。

外部工具来源

  • MCP Servers — 通过 Model Context Protocol 连接的外部服务（CLI apps、远程 API 等）
  • CLI Apps — 注册的命令行应用，适配为 tool
  • Plugin Contributions — 插件系统贡献的自定义 Tools

LoopExtension Protocol — 扩展点

Capability 通过实现 LoopExtension Protocol 融入 chat loop：

class LoopExtension(Protocol):
    name: str                              # 能力名
    owned_tools: tuple[str, ...]          # 专属 tools

    def is_active(context) -> bool:
        # 是否在当前 turn 激活

    def system_block(context, *, language, prompts) -> PromptBlock | None:
        # 贡献 system prompt 片段

    def augment_kwargs(tool_name, kwargs, context) -> dict:
        # 注入服务器私有 kwargs

    def pre_loop(context, stream, *, usage=None) -> PromptBlock | None:
        # 可选：第一次 LLM 调用前的预传递

KnowledgeCapability — 知识独占模式

与普通 LoopExtension 不同，KnowledgeCapability（如 IMA、Obsidian、MarginNote4）独占整个工具面：当激活时，完全替换 chat 的 tool surface 为自己的 owned_tools，模型通过这些专属工具直接推理知识库，而非固定流水线。
